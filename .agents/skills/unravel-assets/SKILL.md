# Unravel assets

Source files and their `.meta` sidecars under a protocol's `data/` folder, the editor-only asset
compiler that writes them to `compiled/`, the asset watcher that triggers it, and the runtime
asset manager and handles that load compiled files. Owns `engine/engine/assets/`,
`editor/core/asset_compiler/` and `editor/editor/assets/`. Shader and material-graph compiles run
here, but their contracts belong to `unravel-rendering` and `unravel-materials`; the script
library build belongs to `unravel-scripting`. Driving imports over MCP is `unravel-editor-mcp`
(guide `editor_data/data/mcp/skills/assets.md`).

## Gotchas

Ids and `.meta`:

- A source's id lives in its `.meta` (`<file>.<ext>.meta` beside it, JSON of `asset_meta`). A file
  moved or renamed without its `.meta` gets a new id, and every reference by uid breaks. Move,
  rename, copy and delete through `asset_actions::rename_entry` / `duplicate_entry` /
  `move_to_trash` (`restore_from_trash` brings a batch back with its ids).
- A missing `.meta` is regenerated: under `engine:` and `editor:` the id is derived from the path
  (`asset_manager::generate_metadata`), under `app:` it is random. An engine asset keeps its id
  across a regenerate, never across a rename.
- Two files with one uid (a copy made together with its `.meta`): the file the watcher indexes while
  the other already holds the uid gets a fresh id, and references keep the holder
  (`find_other_holder_of_uid`, `asset_watcher.cpp`).
- Built-in shape ids (`engine_data/data/meshes/*.emesh.meta`) are `generate_uuid("engine:/embedded/<name>")`,
  which projects reference in bulk: never regenerate them. Keys of that form resolve to the shape's
  file (`asset_manager::resolve_key`).
- Code that moves a loaded asset calls `am.rename_asset<T>(old_key, new_key)` right after the move:
  the watcher may report the move as a delete, which unloads the asset from every user.
- The inspector, the MCP tools and the project audit read import settings from the asset database,
  and the watcher reads a `.meta` into it only when the source file changes. Code that writes import
  settings to a `.meta` gives them to the database too: `editor_actions::save_import_settings` does
  it for editor code, and the mesh importer's texture tagging calls
  `asset_manager::add_asset_info_for_path`. A write that skips it compiles the asset right while the
  editor shows the old settings until it restarts, and the next Apply writes those back.
- A deployed game has no `.meta`: its asset index holds each asset's location and what the runtime
  reads of its import settings, a record each importer declares (`get_shipped_info`, such as
  `texture_shipped_info`). Runtime code reads import settings only through
  `asset_database::meta::get_shipped_info`, which answers from the importer in the editor and from
  the index in a build; a new fact joins its importer's record. Desktop builds hide a missing fact
  where the format alone answers (BC5 is always a two-channel normal map); ASTC builds do not.

Compile and recompile:

- Writing a `.meta` is what compiles its asset: the cache syncer watches `.meta` files. The source
  syncer rewrites a changed file's `.meta` unless that `.meta` changed in the same watcher batch
  (`fs::syncer` passes those entries to the callbacks), so a file arriving with its `.meta` compiles
  once. The first listing writes only missing or re-ided `.meta` files.
- Each `.meta` write asks for a compile, and a compile reads the settings when it starts. The watcher
  starts every compile through `asset_compiler::compile_gate` (`editor/core/asset_compiler/compile_gate.h`):
  while a file compiles, a request for it starts nothing and makes that compile run once more when it is
  done. Without it two compiles of one file overlap and the slower one wins, whichever started first: a
  texture's first compile as a color texture finished after, and wrote over, its compile as the normal
  map a model import had made of it. A new place that starts a compile goes through the gate too.
- Multi-file sets (a `.gltf` with its `.bin` and textures) are written under
  `fs::watcher::scoped_pause`, as `editor_actions::import_files` does, so no compile sees half a set.
- A compiled file is current while its manifest (`<compiled>.manifest`) matches: the fingerprint of
  source + `.meta` + `asset_compiler::resolve_dependencies<T>` files (text hashed with line endings
  normalized), `ex::get_format_version<T>()`, and for textures and audio clips the compile-parameters
  string (project defaults included). An output change that moves none of these is never recompiled.
- The output is a function of the compiler code too: an importer, baker, generator or card-builder
  change that alters output bumps `ex::get_format_version<T>()` (`asset_extensions.h`); a texture
  compile change bumps the version inside the compile-parameters string (`texture_target.h`).
- Compiled assets are binary documents (`serialization/binary_archive.h`), read by name like JSON: a
  field goes anywhere in SAVE and LOAD and an absent one keeps its value. `save_to_file_bin` writes
  through `serialization::write_binary` (output format binary while it saves; false when the
  `try_save` the lambda returns failed) and `load_from_file_bin` takes the file whole with
  `fs::read_readable_file` - a deployed game's packed file in place, not copied - and reads it with
  `serialization::read_binary`, which refuses a file that is not a binary document - an older compile -
  quietly, leaving it to its caller to treat as not current, and a broken one with a warning; neither
  throws. Write compiled files in binary mode. A check that needs a large
  file's first fields reads only its start (`serialization::read_binary_head`).
- Scenes and prefabs compile from their JSON source to binary documents
  (`write_binary_document_file`, `serialization::json_to_binary_document`). A buffer of either format
  loads through `serialization::read_document`.
- Dense lists of one shape in compiled data (triangles, bone weights, animation keys) are saved as
  `serialization::packed(list)` (`serialization/types/packed.hpp`): rows of bare values in a binary
  document, an ordinary array in JSON. Rows are read back by the code that wrote them, so the
  element's LOAD reads every value its SAVE wrote, a change to that element bumps the asset's format
  version, and no prefab override reaches inside the list: never use it for component data. A value
  in the rows that fails, or elements that read less or more than was saved, fail the whole list,
  which keeps what it held; an element must save at least one byte.
- What only a compiled file keeps (a graph material's binding and shader hash) is saved by the binary
  archive (`ser20::oarchive_binary_t`); its load reads it when present.
- Vectors, quaternions and colors are one packed value in a binary document and an object of named
  numbers in JSON (`serialization/packed_value.h`): their serializers go through
  `serialization::serialize_components`, and a new type of that shape specializes
  `ser20::is_packed_value` beside its serializer. A filtered load still takes one component by its
  name (`position/x`), and a document converted from JSON keeps the object form, which loads too.
- An older build may open a project this one compiled. It recompiles every asset whose manifest format
  version differs from its own, so a change to what a compiled file holds bumps `get_format_version`.
  Binary documents start with 32 zero bytes: an older build that reads one without a manifest (a graph
  material's shader files) reads empty sizes and compiles again instead of allocating what the header
  says. Source files stay the JSON every build writes: never change their text for the binary format.
- A new `*_importer_meta` registers with `SERIALIZE_REGISTER_TYPE_WITH_NAME`
  (`engine/engine/meta/assets/asset_importer_meta.hpp`); the `.meta` names it by that string.
- `asset_meta::importer` and `header` are polymorphic: cast with `safe_pointer_cast<T>` to the leaf
  (`texture_importer_meta`, `mesh_header_info`, ...). The cast compares the exact type, so
  `asset_importer_meta` or any other base never matches.
- A new source's `.meta` is written with `asset_compiler::create_default_importer` settings, and
  `read_importer<T>` falls back to `read_or_create_importer`, which saves the defaults and returns
  them: a compile never runs without settings, and new types keep both paths.
- Compile jobs run in the editor process, several at once on its pool: importers bounds-check every
  index read from a source file (vertices, bones, meshes) and use no unsynchronized process-wide state.
  Format traps: [texture-and-mesh-import.md](texture-and-mesh-import.md).

Loading:

- `asset_handle::is_ready()` only reads the task state and never submits a deferred load. Scene
  loads register handles deferred, and idle assets are demoted to deferred
  (`asset_storage::evict_unused`), so `if(!h.is_ready()) return;` never loads an asset nothing else
  touches. Non-waiting code uses `try_get()` (submits; null until loaded) or `visit()`.
- Reproduce deferred-load bugs through a saved scene opened in a fresh editor process: assets set
  over MCP or just imported load immediately and hide them.
- Skip or wait by what the consumer does without the asset. A late result that is cosmetic (draws,
  bounds, GI cards) skips with `try_get()`. Anything integrated over time or relied on by other
  objects (colliders, spawns, gameplay state) waits with `get()` at first use or gates activation on
  a prefetch. A "briefly wrong" caveat is a design question for the user, not a footnote.
- `get()` returns the shared empty asset (never null) after a failed load or for an empty handle;
  `try_get()` returns null while loading. Tell a failure apart with `asset_handle<T>::is_empty(ptr)`.
- `visit(f)` passes a raw pointer valid only inside `f`. Inside it, never let the pointer out and
  never wait (`get()`, or `try_get` / `visit` with `wait`): a wait there holds back every due free.
- `peek()` has no side effects (no load, no access stamp): only for walks over resident assets.
- A thread that waits on a load is registered with threadpp (`tpp::this_thread::register_this_thread()`);
  a plain `std::thread` aborts in the wait.
- Opening or closing a project unwatches `app:/` and unloads every `app:` asset
  (`asset_watcher::unwatch_assets`): a run after a reopen is not a warm run.
- `.meta` files and import settings read through `try_load`
  (`engine/core/serialization/serialization.h`): a missing name is skipped, a value that throws
  leaves the reader at the node it started in, and JSON loads log neither, so a misspelled setting
  keeps its default without a message. Every save logs the failure, and so does every load of a
  compiled file read through `serialization::read_binary` (`reportsFailedLoads`): only the engine
  writes those, from the types that read them, so a value that will not load means the data and the
  code disagree. Documents converted from JSON and copies made inside the process read as quietly as
  JSON.

Generated by-products:

- Every mesh vertex is `gfx::mesh_vertex` (44 bytes): it always holds a vertex colour (white when the file has
  none) and a second UV set (a copy of the first), because bgfx gives a shader no default for a missing attribute.
  The mesh records which the file had (`load_data::has_vertex_colors`, `uv_set_count`, shown in `mesh::info` and
  `assets_get_mesh_info`); LOD simplification weighs them only then. Import Vertex Colors off removes the colours in
  Assimp (`aiComponent_COLORS`). A glTF material used by a mesh with `COLOR_0` imports with the Standard surface's
  `multiply_vertex_color` on (the specification's meaning); FBX and OBJ materials leave it off.
- Morph targets (Assimp's anim meshes) import as sparse deltas merged by name across the file's meshes
  (`mesh::load_data::morph_targets`, `engine/engine/rendering/morph_targets.h`; the importer half is
  `mesh_import_morphs.cpp`). Assimp welds by the base vertex alone, so before post-processing every vertex of a mesh
  with targets gets a morph signature in its first free texture coordinate set (a closed mouth's lips stay apart),
  removed again after, from whichever set post-processing moved it to (`remove_morph_signatures` finds it by its
  mark); Optimize Meshes and Split Large Meshes drop anim meshes and are skipped for such a file. Only
  ConvertToLH, Scale, SortByPType and JoinVertices keep anim meshes in step: a new post-process step must too, or
  the deltas index the wrong vertices. The bind-space correction moves anim meshes with their mesh. The skin split
  copies a morphed vertex's deltas to its copies (`add_morph_vertex_copies`).
- FBX blend shape channels are not in Assimp's data: a channel with in-between shapes shows as consecutive anim
  meshes sharing the channel's current percentage as their weight (a one-shape channel has weight 1), and FBX morph
  keys index channels. The importer keeps each such run's last (full) shape and maps keys through it
  (`get_morph_channel_shapes`); two adjacent in-between channels at the same percentage merge. glTF keys index
  targets, and only glTF's `mWeight` is a default weight. An exporter that writes a shape's normals as zero deltas
  gives Assimp shape normals equal to the rest ones: Morph Normals Import calculates a target's normals when none of
  the file's turn.
- A clip's file keeps its morph curves; `compile<animation_clip>` adds the import settings' curves over them by
  name instead of replacing the list.
- A file an import writes beside its source (a model's default `.mat`) is written only through
  `generated_asset::write_file`: it writes the `.meta` with a content fingerprint
  (`asset_meta::generated`) before the content, rewrites the file while it matches, and keeps it once
  edited. Reset to Imported is `generated_asset::release_to_import`.
- A generated file without a fingerprint record is replaced only when the import's `is_older_import`
  check recognizes an earlier import's output; every other untracked file is kept. Widening that
  check is the user's decision.
- A renamed by-product moves with `generated_asset::adopt_former_file` (keeps its id); files an
  earlier import wrote that the current one does not are deleted only through
  `generated_asset::remove_unreferenced_files`, which keeps any file a text asset names.

File formats and engine data:

- A new or changed asset file format carries behavior in real fields or directives, never in
  comments, and lists items one per line (the `[variants]` section of an `.eshader`) before any
  rule language.
- An asset in `ENGINE_FOLDERS_SHIPPED_WHEN_USED` that the engine loads by path is listed in
  `ENGINE_LOADED_KEYS` (`engine/engine/defaults/engine_asset_keys.h`), or a deploy that ships only
  used assets leaves it out.

## How it works

Keys and folders, for a protocol `app`, `engine` or `editor`:

```text
app:/data/Models/hero.glb            source
app:/data/Models/hero.glb.meta       uid, type, importer settings, generated record
app:/compiled/Models/hero.glb.asset  compiled output (ex::get_compiled_directory)
app:/compiled/Models/hero.glb.asset.manifest
```

`engine_data/` and `editor_data/` are copied into `<bin>/data/engine` and `<bin>/data/editor` by
the `engine_data` / `editor_data` targets, so the editor compiles engine assets inside the runtime
tree. A deployed game reads the asset index (`assets.index`) and the compiled files from the
protocol's `content.pak`; it never compiles.

The pipeline in the editor (`asset_watcher::watch_assets`):

1. Meta syncer (`data/` -> `.meta`): creates, re-ids or rewrites `.meta` files and keeps the asset
   database (uid -> location + `asset_meta`) current.
2. Cache syncer (`.meta` -> `compiled/`): on the initial listing, compiles what
   `needs_recompilation<T>` reports; afterwards, every `.meta` write schedules `compile<T>` on the
   thread pool. Dependency watchers recompile includers when an included file changes.
3. Compiled watcher (`watch_synced<T>`): a new or changed `.asset` reloads the asset
   (`get_asset<T>(key, load_flags::reload, load_mode::deferred)`), a removed one unloads it.

Handles: `asset_handle<T>` is a shared link whose state (uid, id, load task, resolved asset) is
immutable and replaced whole under an epoch guard. A reload publishes a new state; the old one,
and the asset it resolved, is freed by `asset_manager::free_retired_handle_states()` once per frame
(`engine/engine/engine.cpp`) when no reader can still see it. `get_asset` loads immediately by
default; scene deserialization registers handles deferred
(`engine/engine/meta/assets/asset_handle.hpp`).

Built-in shapes are `engine_data/data/meshes/<name>.emesh` files: a `mesh_shape` description
(`engine/engine/rendering/mesh_shape.h`) that the mesh importer builds, so the compile bakes their
distance fields and cards like any model.

## Procedures

- Add an asset type, importer or import setting: [add-asset-type.md](add-asset-type.md).
- Texture formats, mesh import, skinning and assimp traps:
  [texture-and-mesh-import.md](texture-and-mesh-import.md).
- Content packages (`.unravelpkg`): [content-packages.md](content-packages.md).
- Import files from code: `editor_actions::import_files` then `editor_actions::wait_import_jobs`.
  Over MCP: `assets_import_batch` from a staging folder outside the project; never write fetched files
  into `app:/data` directly.
- Add a built-in shape: one `.emesh` plus a `.meta` with a fresh id, LODs off, SDF resolution 64. A
  generator change bumps `ex::get_format_version<mesh>()`.

## Verify

- Suites (`unravel-tests --suite "<name>"`, runner and trees: `unravel-build-verify`):
  `asset handle`, `asset writer`, `asset references`, `asset packs`, `generated assets`,
  `fs syncer`, `fs watcher`, `mesh shapes`, `mesh import heuristics`, `mesh skinning`,
  `settings profiles` (texture formats per target), `normal map green`, `audio clip encoding`,
  `content packages`.
- Build `engine` and `editor` (the compiler is editor code), and `tests` when a suite changed.
- Smoke in an editor: import through `assets_import_batch`, wait for the ready state, reimport after a
  `.meta` edit, then open a saved scene that uses the asset in a fresh editor process.
